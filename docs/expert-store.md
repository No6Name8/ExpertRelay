## Expert record layout

One record per expert, all the same size, back to back from offset 0, so every record starts on a
4096-byte boundary. One unbuffered read of `record_size` bytes loads a whole expert:

```
[gate_proj int8][up_proj int8][down_proj int8][gate scales f32][up scales f32][down scales f32][zero pad]
```

| Matrix | Shape |
|---|---|

| up_proj | 1408 x 2048 |
| down_proj | 2048 x 1408 |

## Quantization

weight-only int8, symmetric, per-output-channel (per-row) absmax: `scale_r = max|W[r,:]| / 127; Q = clip(round_half_even(W / scale_r), -127, 127)`.
Kept fp32: norms, biases, mlp.gate (router), mlp.shared_expert_gate. References: Krishnamoorthi 2018, arXiv:1806.08342; Dettmers et al. 2022 (LLM.int8()), arXiv:2208.07339.

Error is measured on the serialized bytes: each record is parsed back, dequantized, and compared
with the original bf16 values. `rel_fro_error` = ||W - W_hat||_F / ||W||_F. `max_abs_error_over_scale` is the largest
per-element error in units of the row's step size. Exact rounding bounds it at 0.5; values a few
millionths above that come from float32 rounding in the division, not from a quantization bug.
